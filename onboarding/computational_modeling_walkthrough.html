2. Reuse Code & Keep Simple

Keep one clear path from inputs to observables.

Inputs
Existing parameter defs
→
Equations
Exact update, BC & noise order
→
Observables
Established libraries, direct calls
Rule: No duplicate paths or speculative abstractions; optimize only proven bottlenecks against a reference within tolerance.

3. Classify Failures Before Editing

Isolate a representative case to identify the cause.

Implementation Error
Code differs from intended math → Fix code
Numerical Error
Coarse resolution, tolerance, or sampling → Check convergence
Model Limitation
Resolved math misses target behavior → Revise physics
Rule: Treat any equation, assumption, parameter-meaning, or BC edit as a scientific model revision — never call it a code correction.

4. Verify and Validate With Proportional Evidence

Pre-declare quantitative tolerance, support, falsification, and inconclusive criteria; run smallest authorized check.

Code Verification
Derivations & exact/manufactured solutions
Solution Verification
Convergence, stability & conservation
Physical Validation
Independent empirical data & uncertainty
Rule: Keep calibration separate from validation, keep production solver baselines untouched, use ensembles for stats, and never launch unauthorized runs.

5. Record Provenance & Hand Off Docs

Log reproducible run state and preserve negative findings.

Run Log (MIASE/NASEM)
Git rev/diff · params & units · seeds & controls · outputs
Keep Distinct
Model name ≠ release (model-versioning.md) ≠ git rev ≠ run settings
Docs Handoff
Pass equations, sources, gaps & header field Model version control name: (confirmed model/version identifier) to $model-documentation
Rule: Preserve failed checks, inconclusive runs, regime limits, and superseded findings; doc handoffs never authorize runs.

6. Verify Completion & Stop Cleanly

Confirm alignment, report limits, and stop without extras.

Aligned
Formulation, code, checks, docs & provenance match
Reported
Findings, record paths, uncertainty & unperformed checks
Clean Stop
Negative or inconclusive evidence also completes the task
Rule: Never claim untested execution or broader validity, and never start unrequested cleanup, additions, or sweeps.
